# Internationalization (Indonesian and English)

Read this before you add or change any text the user sees.

## Languages

- Supported: `id` (Bahasa Indonesia) and `en` (English).
- Fallback language: `en`.
- Detect the language from the browser on first visit. Let the user change it from a language switcher in the shell. Save the choice in `localStorage`.

## Library

Use `i18next` with `react-i18next`, and `i18next-browser-languagedetector` for detection. Setup lives in `shared/i18n/`:

```
shared/i18n/
├── index.ts                  init, language list, change helper
└── locales/
    ├── en/
    │   ├── common.json       shared labels: buttons, dates, generic states
    │   ├── auth.json
    │   ├── team.json
    │   └── ...               one file per feature
    └── id/
        ├── common.json
        ├── auth.json
        ├── team.json
        └── ...
```

## Rules

- **No hard-coded user-facing text.** Every label, title, placeholder, button, empty message, toast, and validation message comes from a locale file.
- **One namespace per feature.** A feature's text lives in `locales/<lang>/<feature>.json`. Shared text lives in `common.json`.
- **Keys use dots and describe the place, not the look.** Example: `team.members.empty.title`, not `team.bigGreyText`.
- **Every key exists in both languages.** A test compares the two files and fails when a key is missing in one of them.
- **Plurals and interpolation use i18next features.** `count` for plurals, `{{name}}` for values. Do not build sentences by concatenating strings.
- **Dates and numbers use `Intl`** with the active language. Do not format them by hand.

## Where translation is called

- Views may call `t()` for static labels. That is rendering.
- ViewModels call `t()` whenever a message depends on process state: an error, a success toast, a confirmation text, or a computed status label. The View receives the finished string.

```ts
// team.viewmodel.ts
const { t } = useTranslation('team')
return {
  removeSuccessMessage: t('members.removed', { email }),
}
```

## Server messages

The backend returns English `error` messages. Until the server sends a stable error code, the portal shows the backend text as received. See `error-handling.md`. Do not translate backend text by matching its wording.

## Checklist for a new screen

1. Add the keys to `en/<feature>.json` and `id/<feature>.json` at the same time.
2. Use `useTranslation('<feature>')` in the View or ViewModel.
3. Switch the app to Indonesian and check the screen for overflow, since Indonesian text is often longer than English.
4. Run the locale key test.
